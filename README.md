# Keyvisor

Keyvisor is a command-line SSH agent and key manager that keeps your SSH
signing keys inside a TPM 2.0 chip. Keys are generated by the TPM and cannot be
exported or backed up in a usable form. It is available for Fedora from
[COPR](https://copr.fedorainfracloud.org/coprs/nexryai/keyvisor/).

Keyvisor has no graphical interface. You manage keys with the `keyvisor`
command and use the `keyvisor-agent` service as your SSH agent.

## Requirements

- A Fedora system with TPM 2.0 enabled in firmware.
- An OpenSSH client.
- Your user account in the `tss` group, so it can access `/dev/tpmrm0`.

Check that a TPM is available:

```sh
ls -l /dev/tpmrm0
```

## Install

Enable the COPR repository and install the package:

```sh
sudo dnf copr enable nexryai/keyvisor
sudo dnf install keyvisor
```

Add your user to the `tss` group, then log out and log back in so the new group
membership takes effect:

```sh
sudo usermod -aG tss "$USER"
```

Do not run Keyvisor with `sudo`. Keys and configuration belong to your own user
account.

Enable the SSH agent socket:

```sh
systemctl --user enable --now me.nexryai.keyvisor-agent.socket
```

Point your shell at the Keyvisor agent socket. Add this line to your shell
profile (`~/.bashrc`, `~/.zshrc`, or equivalent), then open a new terminal:

```sh
export SSH_AUTH_SOCK="${XDG_RUNTIME_DIR}/keyvisor/agent.sock"
```

Verify that the agent is reachable:

```sh
keyvisor agent status
ssh-add -L
```

## Create a key

Create a key that can sign without a PIN:

```sh
keyvisor key create --name "Work laptop" --authorization none
```

No-PIN keys are convenient for unattended use, but any process running as your
user can request a signature through the agent socket. Keyvisor asks for
confirmation before creating one. Add `--yes` for scripted setup.

Create a key protected by a TPM PIN instead:

```sh
keyvisor key create --name "Personal" --authorization pin
```

The PIN is required for every signature, is never stored, and failed attempts
are rate-limited by the TPM. In a GNOME session, Keyvisor opens the
`pinentry-gnome3` dialog. In a terminal, it reads the PIN from `/dev/tty`
without echoing it.

Both commands print the new key ID. Use `--algorithm ecdsa-p384` if you need a
P-384 key; the default is ECDSA P-256.

List your keys and display the public key for a key:

```sh
keyvisor key list
keyvisor key show KEY_ID
```

Copy the `Public key:` line into GitHub, GitLab, or any other service that
accepts SSH public keys. To test the agent:

```sh
ssh -T git@github.com
```

Keys are bound to the TPM that created them. You cannot move a key to another
machine, so keep a separate recovery key for emergency access.

Delete a key when you no longer need it:

```sh
keyvisor key delete KEY_ID
```

## Use a PIN-protected key

With a graphical session, just run SSH or Git normally. Keyvisor displays the
pinentry dialog when a signature is requested.

In a headless session, wrap the command so Keyvisor can prompt in the same
terminal:

```sh
keyvisor exec -- ssh -T git@github.com
keyvisor exec -- git fetch
keyvisor exec -- git push
```

If wrapping the command is not practical, start the operation in one terminal
and approve the pending request from another:

```sh
keyvisor authorize
keyvisor authorize REQUEST_ID --terminal
```

Pending requests time out after the configured authorization timeout.

## Configuration

View and change non-secret settings:

```sh
keyvisor config list
keyvisor config set authorization-timeout-seconds 60
keyvisor config set history-enabled false
```

The authorization timeout accepts 10–120 seconds. Restart the agent after
changing a setting:

```sh
systemctl --user restart me.nexryai.keyvisor-agent.service
```

Signing history contains timestamps, key names, authorization policy, and the
result of each request. It never contains signed payloads.

```sh
keyvisor history
keyvisor history --format tsv
```

## Command overview

| Command | Purpose |
| --- | --- |
| `keyvisor key create` | Create a TPM-backed SSH key |
| `keyvisor key list` | List keys |
| `keyvisor key show ID` | Show key details and public key |
| `keyvisor key delete ID` | Delete a key |
| `keyvisor agent status` | Check whether the agent is running |
| `keyvisor history` | Show signing history |
| `keyvisor authorize [ID]` | Approve a pending PIN request |
| `keyvisor exec -- COMMAND` | Run a command with terminal PIN entry |
| `keyvisor config list` | Show configuration |
| `keyvisor config get NAME` | Read one setting |
| `keyvisor config set NAME VALUE` | Change one setting |

Run `keyvisor --help` for a quick summary.

## Troubleshooting

**`/dev/tpmrm0` is missing**

The TPM may be disabled in firmware, or the kernel may not have loaded a TPM
driver. Check the kernel log:

```sh
sudo journalctl -k -b | grep -i tpm
```

**Permission denied when opening the TPM**

Confirm that you are in the `tss` group and that the device is accessible:

```sh
id
ls -l /dev/tpmrm0
```

Log out completely and log back in after changing group membership.

**SSH does not use Keyvisor**

Confirm that `SSH_AUTH_SOCK` points to Keyvisor in the current shell, and that
the socket is active:

```sh
echo "$SSH_AUTH_SOCK"
keyvisor agent status
systemctl --user status me.nexryai.keyvisor-agent.socket
```

**The agent is not running**

Start it through socket activation:

```sh
systemctl --user enable --now me.nexryai.keyvisor-agent.socket
```

## Security notes

- Private key material is generated by the TPM and never leaves it.
- Keyvisor cannot export or import private keys and has no software fallback.
- PINs are never stored, cached, or passed in command arguments or environment
  variables.
- A no-PIN key allows any process with access to your agent socket to request
  signatures. Use a PIN-protected key if that risk is not acceptable.
- Authorization prompts are a safeguard against accidental use, not a defense
  against malicious code already running as your user.

## Uninstall

```sh
systemctl --user disable --now me.nexryai.keyvisor-agent.socket
sudo dnf remove keyvisor
```

Remove `$XDG_DATA_HOME/me.nexryai.keyvisor` (usually
`~/.local/share/me.nexryai.keyvisor`) and
`$XDG_CONFIG_HOME/me.nexryai.keyvisor` (usually
`~/.config/me.nexryai.keyvisor`) if you also want to delete your key records
and settings.
